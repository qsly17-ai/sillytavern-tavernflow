# 清酌 TavernFlow 0.5.0 验收记录

目标是手机通过云酒馆打开大设置、切换长聊天，以及 MVU 等后台任务发起和结束时的交互卡顿。目标宿主为 SillyTavern 1.19.0（7e8663cd9）。证据分为确定的存档缺陷、已测的局部耗时和仍需真机确认的体感。

## 发现与处理

1. **群聊错误响应可能被当作空档。** 旧验证器接受单聊和群聊共用的空对象，原生群聊随后把非数组当作空聊天。新版只允许新单聊使用空对象。群聊必须收到完整数组，否则恢复读取；隔离真酒馆注入一次空对象后重新读到原聊天，后续磁盘内容未被清空。
2. **启动与切换重复解析。** 弱网恢复层已验证完整 JSON，消费端仍从头解析。现在同一完整响应只解析一次；克隆、读取文本、其他包装器替换了设置字符串、锁定或已消费的响应仍按各自语义处理。读失败不制造空值。网络传输、图片与角色脚本加载仍然需要时间。
3. **辅助模型准备重复处理。** 核验过的酒馆助手先给全部历史跑提示词正则、构造消息，再保留指定数量；组装保留的历史时，逐条唤起提示词面板重绘。清酌仅在可保持原生结果时省略丢弃部分的转换，并合并同一请求的重复刷新。老楼可能触发变量修改、随机宏或无法安全识别的行为时，保留原路径。不会改模型、历史数量、世界书、消息原文或助手磁盘文件。通过助手的这类调用可以受益；直接向模型接口发请求的其他插件不经过此路径。
4. **回包附近的大存档。** 保留原生同步 JSON 快照以固定保存时点；Worker 已就绪且确切接管时，不在手机主线程重复编码/压缩。其他包装器需要原请求时，仍按原生流程；确定超过宿主压缩窗口时不分配无用的编码副本。服务端核对无变化保存时不再重复生成规范 JSON；给长聊天应用小改动时不再把全部旧楼文本重新转义再解析。Worker 最多留六份、总计 32 MiB 的规范快照；淘汰后仍保留冲突检查。
5. **插件更新后旧快路失效。** 恢复已核验的助手 4.12.2 重前端减负和小白X 3.2.7 空清理。在真实助手接管约 5.8 万字符的内嵌页面时，临时保护与释放各一次、超时零次；开关前后是同一 iframe，按钮两次点击有效。小白X 双空清理跳过一次，加入记录后原生清除一次。无待接管内容时不常驻观察整个聊天树。

## 浏览器对照

390×844 Chromium，CPU 降速四倍。读写样本均为合成数据，预热后交替运行五轮，取中位数；第二批用实际 gzip 补测 5.6 MB 保存。以下不是整页下载、模型响应或完整保存往返时间。

| 同一操作 | 0.4.1 | 0.5.0 |
|---|---:|---:|
| 读取并解析 20.2 MB 设置 | 609 ms | 306 ms |
| 读取并解析 500 楼、14.1 MB 聊天 | 353 ms | 182 ms |
| 同一 500 楼聊天，原生保存前准备 | 200 ms | 62 ms |
| 200 楼、5.6 MB 聊天，保存前准备（旧版会 gzip） | 175 ms | 32 ms |

独立的服务端计算对照中，500 楼、30.0 MB 聊天只改一处，单独应用差量中位数 49.5 → 1.1 ms。仍要进行完整性核验和原生落盘，不能把这个数字当成一次保存时间。

## 真实宿主与回归边界

隔离酒馆安装真实助手 4.12.2，以相同的合成聊天从 generateRaw 发起，模型接口只返回固定 JSON，随后真实调用助手写入末楼变量，并从磁盘检查值、楼层数、未知字段。比较发往模型的实际 messages 内容摘要，另用每楼自增的宏检查不能跳过的副作用。未使用用户聊天或调用付费模型。

- 20 / 100 / 500 楼，分别覆盖无提示词正则、删除型规则、匹配后需原生替换、变量宏，以及取最近 2 楼和 24 楼的场景。可优化的 500 楼、保留 2 楼请求跳过 498 楼转换；带变量自增的对照分别执行足 20、100、500 次。提示词摘要前后一致。普通轻规则并不稳定触发秒级卡死；冷启动的分词或其他工作仍可占主要时间。
- 在 500 楼的旧消息加入重复标记、用删除型规则处理，再仅取最近 2 楼；从请求开始到发给模型，原助手三次中位数 471 ms，开启适配后 270 ms；每次均核对模型输入和变量落盘。回包后的长任务没有稳定改善。样本少，发起总耗时含异步分词，不将其当作手机主线程占用。
- 设置、单聊、群聊的旧页保存冲突均被拦截。模拟服务器写入成功但回包中断时，不自动覆盖重试，独立资源仍可保存，页面保留未保存的修改。原生强制覆盖的确认框、确认期间的并发变更、Quick Reply 专项读取和失败回退也在隔离浏览器验证。
- 面板可手动记录两分钟内页面长任务（至少 50 ms），分别显示助手发起、结束后 2.5 秒内的峰值；切到后台自动结束，不记录提示词或变量，不上传。前台长任务的时间重合不能单独证明是哪个插件造成。

固定版本宿主的自动化回归共 181 项，全部通过，无跳过。扩展清单检查无错误或警告。

适用边界：未在用户实际手机和公网高峰复现同一轮游玩；未测整机耗电，也没有让真实付费模型决定回包内容。完整首次下载、非助手后台插件、不能略过的宏/正则、卡片自身复杂脚本和渲染仍可能造成卡顿。分项数字不能相加，也不代表云端与本地的总加载差距消失。更新后保留草稿，关闭旧标签页重开；可在“扩展设置 → 清酌 → 模块状态”检查是否实际启用。
