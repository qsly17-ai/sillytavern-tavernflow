# 清酌 0.5.1 验收

基线为 `v0.5.0`，宿主固定为 SillyTavern 1.19.0 / `7e8663cd9`。本轮只收敛清酌在长聊天更新和小改存档中反复执行的工作。协议版本、原生请求、楼数、模型和保存权限仍沿用原合同。

| 范围 | 发现与处理 | 必须保持 |
|---|---|---|
| 历史纯文字绘制 | 最新五楼退出清酌的历史队列。同批多条 DOM 改动合并到楼层；浏览器繁忙时，历史队列按小批次继续推进。 | 不移除正文或 iframe；编辑、选择与查看历史立即可用。历史楼因删除变成最新楼时先恢复样式，面板同步更新；移回历史时重测。 |
| 差量计算 | 旧版在父级先对比完整子树，再递归到其子级。新版每层只走一遍，只有真正输出操作才复制路径，数组增删仍沿用原来的一段 splice。 | 合法 JSON 的操作内容、SHA-256、保存冲突和落盘合同不变。 |
| 第三方适配 | 小白X 3.2.8 / 3.2.9 的清理、设置修整和记录计数逻辑已核对；构建改名后更新精确指纹。 | 只跳过两个记录集合已空且设置已完整的操作；未知实现交还原生。提示词模板不增加适配。 |

## 对照与运行证据

Node.js 22，合成 JSON，交替运行 26 对、取后 21 对中位数。每种场景都核对了操作输出。下表只计 `diffValues` 的比较和构造操作时间，未计入快照、哈希、网络或文件写入。

| 差量样本 | 0.5.0 | 0.5.1 |
|---|---:|---:|
| 500 楼、8.38 MB，改最后一楼的一项变量 | 11.73 ms | 5.59 ms |
| 13.42 MB 设置，改一个靠后的选项 | 31.68 ms | 11.76 ms |
| 500 楼样本，追加一楼 | 6.30 ms | 5.25 ms |

独立审查复跑后，末楼变量和晚位置设置仍减少计算时间；单纯追加新楼没有稳定收益。

390×844 Chromium 使用四倍 CPU 降速，实际酒馆加载同一份 500 楼合成聊天。通过原生 `updateMessageBlock` 分 24 批更新最新三楼，每批之间留两帧。两组完成的初始对照中，近期楼层的分类次数从 24 降为 0；浏览器很忙时，旧版的分类仍可能留在队列，无法用这项计数推断整段回包的提速。最终调度复核验证当前楼没有被延后、批量历史编辑立即恢复显示、历史楼新增按钮可获焦点、滚到顶部能显示完整正文。每批至多处理 24 楼，开始下一楼前检查 5 ms 的时间预算；单楼耗时可能超过预算。

实际隔离安装同时使用助手 4.12.2、提示词模板 1.17.10.1、小白X 3.2.9。重楼层约 5.8 万字符，原助手成功交接给互动网页；切换前端保护未更换 iframe，按钮状态保留。模板普通求值、后台编译均返回预期值。小白X 两处记录均为空时，跳过一次空清理且不发额外保存；有记录时走原流程。3.2.8 沿用上一次隔离对照已核对的官方构建指纹。

500 楼辅助生成用真实助手的 `generateRaw`、固定 HTTP 回应和原生变量写回。五次都按请求处理最近两楼，模型输入摘要相同，差量保存成功，未知字段保留。调用与回包附近仍可见长任务，不据此判断高楼层卡顿已经消失。这些测试未调用付费模型。

保存与读取通过真实宿主回归：设置、单聊和群聊能拦住旧页写入；确认覆盖期间新页的写入会保留；连接在文件写完后丢了回执时，当前页保留编辑并提示刷新，没有自动再写。开屏验证了快捷回复只读预设及失败后回到完整设置，聊天切换与群聊异常时可恢复。该组测试无未捕获的浏览器错误。

固定宿主自动化 183 项通过、无跳过；扩展清单和 77 个脚本通过检查。空上下文审查从干净归档复跑了完整测试；10,000 对合法 JSON 的差量操作序列化字节与 0.5.0 一致，应用结果均符合预期。审查发现的面板统计滞后已有针对性回归测试，修订后复核未发现阻止发布的问题。

仍需用实际手机对照高楼层回包和云端开载。0.5.1 沿用同步快照和原生文件落盘，也没有测出整页加载的稳定提速。
