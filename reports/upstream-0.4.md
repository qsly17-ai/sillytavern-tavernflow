# Cloud Lounge Accelerator 研究与清酌0.4取舍

检查对象：[SillyTavern-Cloud-Lounge-Accelerator](https://github.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator)，2.1.69 / `8cddd9773688517996b2121a91b494a8cbebbee8`，AGPL-3.0-only。仅阅读固定版本，没有在用户酒馆执行、安装或复制其源码。

值得吸收的是分阶段看待启动成本、让可选模块在就绪后工作、减少大响应的clone和分支处理、沿用浏览器HTTP缓存。这些原则适合清酌；本版采用完整设置响应的有界异步压缩，并更早准备同一个后台差量保存会话。

本服务器静态核心本已有缓存、Brotli及反代链路。新增根Service Worker既重复，也引入更新与离线状态复杂度。上游的cache.put失败可能影响原本成功的资源请求，不移植。临时裁剪为少量聊天楼层、提前撤遮罩或发业务事件，也不适合需要MVU、助手和模板完整语义的实例。

用户所述概率首次加载挂起有另外的明确等待点：目标宿主getChat的网络读取没有原生超时；模板在CHAT_CHANGED中串行等世界书读取，助手随后才处理正文前端。原生聊天读取失败会走getChatResult，空内存聊天可能触发开场保存调用；不据此断言已经覆盖实际存档，因为宿主integrity还可能拒绝覆盖。上游未直接解决这些等待点。

清酌0.4据此独立实现早期只读恢复：只接管识别出的同源JSON读，完整成功才交回原生；无可见进展超时后自动重试一次，连续失败交给用户；不伪造空聊天、不自动重试写入。当前聊天身份变化时，旧结果不交给新会话；助手历史文件读取保持独立。仍有明确覆盖外情形，见本版验收与审查报告。
