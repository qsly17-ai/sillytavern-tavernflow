# 清酌 TavernFlow 0.4 验收

目标：SillyTavern 1.19.0 / `7e8663cd9`，保留现有 MVU、酒馆助手、提示词模板、小白X、数据库与私人预设。0.4 主要处理弱网读取停滞和启动传输，不扩展为存档中心。

## 本版行为

原生聊天导航经完整源码指纹核验的局部入口进入早期恢复器，业务 fetch 包装链仍完整执行。其他明确启动 JSON 读取按严格签名接入；第三方聊天后台读取保留原有行为。30秒无可见数据后重试一次，设置/全角色列表为60秒；持续传输不限总时间。连续失败显示手动重试和刷新入口，草稿可在框内选择复制。不会把网络失败变成空聊天，不自动重试写入或提前触发业务事件。

完整设置响应采用异步 Brotli q6/window24，256 KiB—64 MiB范围、全局最多两项压缩；超限或异常使用原生响应，无私人缓存。客户端更早准备同一个差量保存 Worker，健康检查包含响应体超时。

## 传输与弱网测量

固定同一份完整设置响应：解压后32,008,511字节，原压缩体4,525,620字节，候选3,835,616字节，减少15.25%，解压字节/SHA一致。这是同一响应的传输量变化，不是整页或手机速度百分比。提高压缩强度有服务器CPU成本，真实HTTP测试确认浏览器协商进入优化路径。

弱网条件为Chromium/CDP，390×844，150ms时延、下行1.5Mbps/上行0.75Mbps。冷启动为新浏览器上下文，暖启动沿用该上下文缓存并重载。测量APP_READY，不把正文iframe全部完成或真实手机就绪混同。

## 正式部署

已按授权在正式1.19.0实例从0.3升级为0.4，并重启对应PM2服务。安装前持久备份三个核心文件及清酌两个目录，升级不改settings；部署时210个数据/预设保护文件逐个SHA保持一致。原有index之外的两份核心脏改保持字节一致；对index去掉自有块、对两个聊天核心逆换自有标记后，分别与安装前备份逐字节相同。

公网全新390×844浏览器确认前后端0.4、早期恢复启用/等待0、差量保存与原优化模块就绪、酒馆助手API可用，无pageerror。清酌“抽屉即时展开”通过原生面板切换、落盘确认、恢复原值并再次落盘；全部既有清酌选项保持原值，包含用户已打开的首屏预取与轻量拖影。默认模型不变、未选择正式聊天或发起生成，NY七项定义和全部预设文件SHA不变。

安装后应复制未发送草稿，关闭所有旧酒馆标签页，再重新打开，确认面板0.4.0。旧页不会自动获得新的head恢复块。

## 已知限制

- 没有手机真机、高峰公网、耗电与内存峰值验收；此次没有新正文模型生成测试。
- 大设置仍完整返回，多个业务插件仍可能重复读取；保留完整业务加载顺序，不能保证每次开屏明显提速。
- 客户端完整缓冲和JSON校验会产生额外内存、解析工作；目前没有客户端响应总字节/并发硬预算。服务端压缩预算不等于全站资源上限。
- 调用者自带取消信号、Request对象、XHR、独立Worker、iframe/远程资源及第三方自身永久异步等待不在全部恢复承诺内。某包装丢弃取消信号时仍可能等待。
- 保留原生合法空聊天语义，不能凭相同的200空响应分辨新聊天与宿主吞掉的文件错误；不是磁盘损坏恢复或全局存档锁。
- 持续慢传不限总耗时，30/60秒是JS能见的响应进展；后台计时器和压缩块会影响判断。
- 首屏预取与轻量拖影仍是实验选项，通用默认关闭，本次升级保留用户已有选项。0.3重前端暖选卡收益不与0.4相加。
