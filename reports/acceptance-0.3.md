## MVU、柏宝绘与页面操作

- 用目标卡真实加载的 Mvu API 解析一条隔离变量更新，保留完整未知字段，写到正确消息楼层后重绘；修改正确读回，再恢复完整原变量。
- 柏宝绘采用**等价回放**：更新正文及当前 swipe → saveChat → MESSAGE_EDITED → updateMessageBlock → MESSAGE_UPDATED。使用实际 bbi_image tag；未调用图片生成服务，不将回放称为完整出图验收。
- MVU 回放总耗时 1003→1063ms；长任务 595→78ms，但计时器最大延迟 621→849ms。tag 回放总耗时 2639→1672ms；长任务 843→739ms，但计时器延迟 930→1329ms。单对样本与不同指标没有一致改善，**不能宣称已经根除 MVU/tag 回写冻结**。
- 原有 MESSAGE_EDITED 消费者会移动 StatusPlaceHolderImpl 标记，因此回放后正文不是逐字节相等；原测试数据明确标记这一点。变量相等、tag 正常写入/移除、3 个 iframe 保留；关闭测试浏览器后，隔离目标聊天已从未改变的正式原文件精确恢复。正式聊天未参与写入测试。
- 主页面真实滚轮向上滚动成功，清酌总开关关闭/开启保持同一助手 iframe；sourceGuard 单开关通过实际点击测试。390×844 下清酌面板边界约 12.05～377.95px，无横向溢出。这是桌面窄屏，不能替代手机真机。
